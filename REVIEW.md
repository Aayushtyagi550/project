# REVIEW.md

Review of the starter `app/main.py`. "Fixed" means fixed in the new `app/main.py`; the helpers were rewritten rather than reused
because several of them are wrong by design (naive datetimes, same-day assumptions), not just by a typo.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Floors to whole minutes **first**, then tests `> 10`. R2 says late when strictly more than 10:00 *seconds-wise* has passed. | Shift 09:30, punch-in 09:40:59 -> returns 0, R2 expects 10. (09:40:01 is also 0.) | Compare elapsed **seconds** with `> 600`, then floor to minutes. |
| 2 | `compute_late_minutes` | Builds the shift start with `punch_in.replace(hour, minute)`: same calendar day, in whatever time zone the datetime happens to be in (not IST). | Overnight shift 22:00-06:00, punch-in 00:30 on the 7th (shift of the 6th) -> 0, expected 150. An aware UTC value 04:35Z (10:05 IST) -> 0, expected 35. | Shift start is computed as an IST instant on the record's **attendance date** (`ist_instant`); everything works on integer epoch seconds. |
| 3 | `compute_work_hours` | `round()` is float/banker's rounding, not half-up (R4). Also no truncation of the instants to whole seconds (R1). | 54 s -> 0.015 h -> returns 0.01 (expected 0.02); 16218 s = 4.505 h -> returns 4.5 (expected 4.51). | `Decimal(seconds) / 3600` quantized with `ROUND_HALF_UP`; instants truncated to seconds at the boundary. |
| 4 | `compute_overtime` | No 30-minute minimum (R3). | Shift end 18:30, punch-out 18:45 -> 15, expected 0. | Count only when floor-minutes >= 30. |
| 5 | `compute_overtime` | Shift end is always on `date_str`, so overnight shifts are wrong; and it subtracts an aware `end` from the naive `punch_out` the starter stores. | 22:00-06:00 shift, out 06:40 next day -> 1480, expected 40. A naive punch-out raises `TypeError: can't subtract offset-naive and offset-aware datetimes` (500). | Overnight shift end is the **next** calendar day; all instants are aware/epoch based. |
| 6 | `compute_*` helpers, `punch_in` | Naive datetimes everywhere: `datetime.fromtimestamp(ms/1000)` and `datetime.now()` use the *server's* time zone; the client has no `tz_aware=True`, so values read back from MongoDB are naive too. The date `d` is the server-local date, not the IST date (R1). | Server in UTC: punch-in at 02:00 IST on the 7th (20:30Z on the 6th) is stored with date 2026-07-06. | `MongoClient(tz_aware=True)`; explicit UTC <-> epoch-ms conversion at the boundary; dates derived in IST. |
| 7 | `GET /health` | Always returns `ok`; never touches MongoDB (contract: 503 when it does not answer). The client also has the 30 s default server-selection timeout. | Stop MongoDB: `/health` is still 200, real requests hang for 30 s then 500. | `ping` the database, 503 on `PyMongoError`; `serverSelectionTimeoutMS=5000`. |
| 8 | `EmployeeIn` / `create_employee` | No validation: any `emp_code`, e-mail, shift format or `joined_on`; `shift_start == shift_end` allowed. | `shift_start: "25:99"` is stored and later crashes the helpers (500); `emp_code: "abc"` is accepted. | Pydantic constraints per the contract (patterns, lengths, valid date, shift_start != shift_end). |
| 9 | `create_employee` | Check-then-insert (`find_one` then `insert_one`) and no unique index: parallel creates both succeed. `created_at` is a naive local `datetime.now()` and is returned as an ISO string, not epoch ms. | 20 parallel POSTs with the same `emp_code` -> several 201. | Unique index on `emp_code`; `insert_one` and catch `DuplicateKeyError` -> 409; `created_at` is a UTC datetime stored, epoch-ms returned. |
| 10 | `list_employees` | `skip = page * page_size` skips the whole first page; `total` counts the entire collection, not the filtered set; no sort (contract: `emp_code` asc); no bounds on `page`/`page_size`. | `GET /employees?page=1` returns rows 21-40. `?department=X` reports `total` of all employees. `page_size=0` / `-5` -> Mongo error (500). | `skip = (page-1)*page_size`; `count_documents(filter)`; sort by `emp_code`; `page >= 1`, `1 <= page_size <= 100` (422 otherwise). |
| 11 | `punch_in` | Unknown employee: `emp` is `None`, `emp["shift_start"]` raises `TypeError` -> 500 instead of 404. | `POST /attendance/punch-in {"emp_code": "NOPE"}`. | `get_employee()` raises 404. |
| 12 | `punch_in` | `status` is a plain `str`: `ABSENT` or `"banana"` get stored. `punched_at` is not validated: seconds (`1783312500`) are accepted and land in 1970; `if body.punched_at` treats `0` as "missing"; floats accepted. | `{"punched_at": 1783312500}` -> 201 with date 1970-01-21. | `Literal["PRESENT","WFH","ON_DUTY"]`; `EpochMillis` = strict int in `[1e11, 4102444800000]` (rejects seconds, floats, strings, bools); `is not None` instead of truthiness. |
| 13 | `punch_in` | Check-then-insert, no unique index: two simultaneous punch-ins both pass the `find_one` and insert. | 10 parallel identical requests -> several 201 and duplicate (emp_code, date) documents. | Unique index `(emp_code, date)`; `DuplicateKeyError` -> 409: exactly one winner, decided by the database. |
| 14 | `punch_in` | R1 overnight rule missing; instants not truncated to seconds. Response leaks internals: adds `id` (the ObjectId) and returns raw datetimes instead of epoch ms. | 22:00-06:00 employee punching in at 00:30 gets the wrong date; response contains `id`. | `attendance_date()` implements R1; truncation; `record_out()` builds the response (no `_id`/`id`, epoch ms, defaults for legacy fields). |
| 15 | `list_attendance` | Loads the **whole collection** into memory, sorts and slices in Python; `total = len(docs)`. Sort only by `date` (no `emp_code` tie-break, so pages are unstable). | ~100k records: seconds of latency and hundreds of MB per request. | Query with `sort` + `skip` + `limit` in MongoDB, `count_documents` for the total; index `(date -1, emp_code 1)`. |
| 16 | `list_attendance` | No validation: `date_from > date_to` silently returns nothing (contract: 422); malformed dates/status accepted; `page=0` gives `docs[-20:0]` (wrong slice); legacy documents without `history`/`half_day` are returned without them. | `?date_from=2026-07-10&date_to=2026-07-01` -> 200 empty; `?page=0`. | Strict date parsing, 422 on inverted range, `status` enum, `page >= 1`; `record_out()` applies defaults. |
| 17 | whole file | No indexes at all (contract: created at startup, idempotent). | `explain` shows `COLLSCAN` for every query. | `ensure_indexes()` in the app lifespan; falls back to a non-unique index rather than refusing to start if seeded data had duplicates. |

**Looked at and decided it is fine**

* `load_dotenv()` - it does not override variables that already exist, so real environment variables win, as the contract requires.
* Endpoints are plain `def`, so FastAPI runs them in a thread pool; the (blocking) `MongoClient` is thread-safe and pooled, so no async/blocking mix-up.
* `doc.pop("_id")` after `insert_one` - `insert_one` mutates the dict, so removing `_id` is necessary and correct (the bug is the extra `id` field, see 14).
* The `localhost` fallback for `MONGO_URI` - convenient for local development, and it is only a default; I kept it because the grader always injects its own values.
